# 视频渲染说明

这里是用代码把演示片渲染成 MP4 的工具链，**不依赖屏幕录制**。

## 为什么不用录屏

演示片 `../视频演示.html` 本质是一个 HTML 动画。录屏会受分辨率、压缩、掉帧影响，
而且需要你手动操作。这个方案改为 **代码逐帧绘制 → 编码成视频**，好处是：

- 不占用你的屏幕，全自动跑
- 帧率稳定 30fps，画质由 crf=18 控制，无录屏压缩损失
- 音频由脚本直接混入，音画对齐精确到帧

## 文件

| 文件 | 作用 |
|------|------|
| `renderer.html` | 渲染器。用 canvas 重绘 7 个镜头，暴露 `window.renderFrame(t)` |
| `render_video.py` | 抓帧 + 编码。用 Chrome 无头加载渲染器，逐帧截图，再调 ffmpeg 合成 MP4 |
| `_frames/` | 临时帧目录（已 gitignore，可自行删除） |

## 依赖

```bash
# Python 包（已装在 WorkBuddy 隔离环境）
pip install playwright imageio imageio-ffmpeg pillow numpy
playwright install chromium        # 若用系统 Chrome 可跳过
```

脚本默认调用系统 Chrome：`C:\Program Files\Google\Chrome\Application\chrome.exe`

## 用法

```bash
# 渲染完整 60 秒
python render_video.py

# 只渲染 20–25 秒（调试用，快速看效果）
python render_video.py 20 25
```

产物：`../麦门省钱助手_演示片.mp4`

## 参数（脚本顶部）

| 参数 | 默认 | 说明 |
|------|------|------|
| `FPS` | 30 | 帧率 |
| `DURATION` | 44.30 | 总时长（秒），**必须与音频长度一致** |
| `W, H` | 1920, 1080 | 分辨率 |
| `OUT_MP4` | `../麦门省钱助手_演示片.mp4` | 输出路径 |
| `AUDIO` | `../audio/narration.mp3` | 旁白音频；不存在则输出无声视频 |

## 音频处理

脚本读 `../audio/narration.mp3`（44.35 秒）。

**关键：`DURATION` 必须等于音频长度**，否则字幕会和声音错位。
第一版就踩过这个坑——音频 44.35 秒，时间轴按 60 秒铺开，
结果音频念完时画面才走到第 5 个镜头，后面 15 秒全无声。

帧数由 `-frames:v` 精确限制，避免 `_frames/` 目录里残留的旧帧被编进视频。

## 修改画面

画面逻辑全在 `renderer.html`，按镜头分函数：

| 函数 | 镜头 | 时间段 |
|------|------|--------|
| `scene0` | 开场提问 | 0–4.55s |
| `scene1` | 三个痛点 | 4.55–10.08s |
| `scene2` | 产品亮相 | 10.08–13.77s |
| `scene3` | 评分榜单 | 13.77–21.41s |
| `scene4` | 交互查询页 | 21.41–29.09s |
| `scene5` | 功能全景 | 29.09–36.39s |
| `scene6` | 收尾 | 36.39–44.30s |

镜头切换点取自音频静音区间的中点，保证换画面时人声正好在停顿。
改完直接重跑 `render_video.py`。改单镜头时用时间参数只渲染那一段，快得多。

## 已知限制

- 渲染速度约 **每秒视频需 5.5 秒**（1329 帧约 4.5 分钟）
- 表情符号依赖系统字体，换机器可能显示不一致
- 这是 canvas 重绘版，与网页版细节有细微差异（见 `../视频演示.html`）
